# Operator review flow

Минимальный проект для передачи заявки из браузера Telegram-оператору и
переключения экрана клиента через WebSocket. Используются FastAPI и aiogram 3.x.

## Запуск

1. Создайте локальный `.env`, скопировав `.env.example`, и укажите в нём токен,
   ID операторского чата и длинный случайный `OPERATOR_CALLBACK_SECRET`.
   При необходимости укажите `OPERATOR_USER_ID`, чтобы разрешить нажатия кнопок
   только конкретному оператору. Не публикуйте реальные значения.
   Создать файл можно командой PowerShell `Copy-Item .env.example .env`.
   Приложения автоматически читают `.env`; переменные окружения, уже заданные
   в системе, имеют приоритет.
2. Установите зависимости: `python -m pip install -r requirements.txt`.
3. В первом терминале запустите backend: `uvicorn main:app --host 127.0.0.1 --port 8000`.
4. Во втором терминале запустите polling бота: `python bot.py`.
5. Откройте `http://127.0.0.1:8000/`.

Бот и backend используют один `.env` и должны иметь одинаковые `BOT_TOKEN`,
`OPERATOR_CHAT_ID` и `OPERATOR_CALLBACK_SECRET`. Для удалённого размещения задайте
`BACKEND_INTERNAL_URL` в окружении бота. При публичном размещении используйте
HTTPS/WSS и не запускайте несколько worker-процессов: активные сессии хранятся
в памяти одного процесса и очищаются при его перезапуске.

## Развёртывание в Railway

1. Создайте приватный GitHub-репозиторий и загрузите туда файлы проекта. Не
   добавляйте `.env`: он исключён из Git и Docker-образа. Если токен бота когда-либо
   публиковался, отзовите его в @BotFather через `/revoke` и используйте новый.
2. В Railway создайте проект из этого репозитория. Добавьте сервис `backend`,
   выбрав сборку из `Dockerfile`. В Variables задайте `BOT_TOKEN`,
   `OPERATOR_CHAT_ID`, `OPERATOR_CALLBACK_SECRET` и `PORT=8000`.
3. В настройках backend задайте healthcheck path `/health` и создайте для сервиса
   публичный домен через Networking → Generate Domain.
4. Добавьте второй сервис из того же репозитория с именем `bot`. В его
   Deploy/Start Command задайте `python bot.py`. В Variables добавьте те же
   `BOT_TOKEN`, `OPERATOR_CHAT_ID`, `OPERATOR_CALLBACK_SECRET`, а также
   `BACKEND_INTERNAL_URL=http://backend.railway.internal:8000`.
5. Откройте выданный Railway HTTPS-домен и проверьте отправку тестовой заявки,
   затем нажмите кнопку решения в Telegram.

Не добавляйте несколько реплик backend: текущие сессии хранятся в его памяти.
Если сервис перезапустится до решения оператора, незавершённая сессия потеряется.
Не публикуйте токен или значения Variables в чате и репозитории.

`quiz_next` пока показывает экран-заглушку. Поля анкеты передаются в чат
оператора только после явной отправки пользователем; ответы дополнительного
опроса не собираются.
