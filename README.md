# Online math tutor

Небольшой учебный тест: ученик отправляет свои данные, репетитор выбирает
задачу или вопрос кнопкой в Telegram, а затем проверяет ответ ученика.
Результаты действий отображаются на сайте по WebSocket. Используются FastAPI
и aiogram 3.x.

## Запуск

1. Создайте локальный `.env`, скопировав `.env.example`, и укажите в нём токен
   Telegram-бота и длинный случайный `OPERATOR_CALLBACK_SECRET`. Не публикуйте
   реальные значения.
   Создать файл можно командой PowerShell `Copy-Item .env.example .env`.
   Приложения автоматически читают `.env`; переменные окружения, уже заданные
   в системе, имеют приоритет.
2. Установите зависимости: `python -m pip install -r requirements.txt`.
3. В первом терминале запустите backend: `uvicorn main:app --host 127.0.0.1 --port 8000`.
4. Во втором терминале запустите polling бота: `python bot.py`.
5. Каждый репетитор открывает личный чат с ботом и один раз отправляет `/start`.
   Бот регистрирует репетитора; ID чата вручную вводить не нужно.
6. Откройте `http://127.0.0.1:8000/` и заполните имя, номер потока, курса и
   класса. Все поля принимают текст без ограничений на длину и набор символов.
   Ученик увидит экран ожидания, пока репетитор не выберет действие.

Все зарегистрированные репетиторы получают анкеты и ответы учеников. В анкете
репетитор выбирает `Отправить задачу` (ученик решает «Сколько будет 6 × 6?»),
`Отправить вопрос` (ученик выбирает «Да» или «Нет» для утверждения «2 + 2 = 4?»)
или `Ошибка, проверьте данные`. Ответ ученика отправляется репетиторам с
кнопками `Верно` и `Не верно, попробуйте ещё`. При неверном ответе ученик может
попробовать снова; при верном урок завершается. При ошибке ученик может
вернуться к анкете и проверить введённые данные. Старые кнопки не применяются к
уже обработанной анкете или ответу.

## Одновременная работа

Более 10 учеников могут работать одновременно: backend обрабатывает запросы
асинхронно и хранит отдельную сессию для каждого ученика. Текущая конфигурация
предназначена для одного процесса backend. Сессии находятся в памяти, поэтому
перезапуск backend завершит активные занятия, а запуск нескольких worker или
реплик без общего хранилища и доставки WebSocket-событий может нарушить обмен.
Для горизонтального масштабирования понадобятся общее хранилище сессий
(например, Redis) и общий канал событий между процессами.

## Развертывание в Amvera

Проект подготовлен для запуска в одном приложении Amvera: Docker-контейнер
запускает веб-сервер и Telegram-бота, а SQLite хранится в постоянной папке
`/data`.

1. Создайте приложение Amvera с типом сборки Docker и подключите этот Git-репозиторий
   (или загрузите файлы проекта в репозиторий приложения). В корне должны быть
   `Dockerfile` и `amvera.yaml`.
2. В разделе переменных приложения добавьте `BOT_TOKEN` и
   `OPERATOR_CALLBACK_SECRET` как секреты. Не загружайте `.env` в репозиторий.
   `BACKEND_INTERNAL_URL` задавать не требуется: бот обращается к backend в том
   же контейнере.
3. Запустите сборку и дождитесь запуска приложения. Конфигурация открывает порт
   контейнера `8000` и монтирует постоянное хранилище в `/data`.
4. В разделе сетевого доступа включите доступ к порту приложения и используйте
   выданный Amvera HTTPS-адрес. Откройте его в браузере и проверьте анкету,
   задание и вопрос с Telegram-кнопками. Для работы в реальном времени
   WebSocket-соединение сайта должно устанавливаться по `wss://`.
5. Проверьте логи приложения: в них должны быть сообщения запуска Uvicorn и
   Telegram polling. Зарегистрируйте репетитора командой `/start`.

Оставьте количество реплик равным одной: состояние уроков хранится в памяти
процесса, поэтому дополнительные реплики без общего хранилища и обмена событиями
между ними приведут к сбоям сессий. При перезапуске приложения активные уроки
сбросятся, но база зарегистрированных репетиторов в `/data/app.sqlite3`
сохранится. Официальные инструкции Amvera:
[Docker](https://docs.amvera.ru/applications/configuration/docker.html),
[постоянное хранилище](https://docs.amvera.ru/applications/storage.html),
[сетевой доступ](https://docs.amvera.ru/applications/configuration/network.html),
[переменные и секреты](https://docs.amvera.ru/applications/configuration/variables.html).

## Переносимый запуск через Docker Compose

Приложение упаковано для Docker Compose и не привязано к конкретному хостингу.
Подойдёт компьютер или сервер с Docker Compose, а также облачный хостинг, который
позволяет запускать контейнеры и оба процесса приложения.

1. Создайте `.env` из `.env.example` и укажите `BOT_TOKEN` и
   `OPERATOR_CALLBACK_SECRET`. Никогда не загружайте `.env` в Git или образ.
   Если токен бота когда-либо публиковался, отзовите его в @BotFather через
   `/revoke` и внесите новый.
2. Запустите сайт и Telegram-бота одной командой:
   `docker compose up --build -d`
3. Откройте `http://localhost:8000`. В логе бота можно проверить запуск:
   `docker compose logs -f bot`; остановить приложение:
   `docker compose down`.

Compose запускает отдельные контейнеры backend и бота из одного и того же образа.
Бот обращается к backend по внутреннему адресу Docker, а снаружи публикуется
только веб-сервис. Регистрации репетиторов хранятся в SQLite в томе `app_data`
и переживают пересоздание контейнера. Для другого локального порта задайте `HOST_PORT`, например
`HOST_PORT=8080`, и откройте `http://localhost:8080`.

При переносе на другой Docker-хост скопируйте код и `.env` безопасным способом,
установите Docker Compose и выполните ту же команду запуска. Для публичного сайта
настройте домен и HTTPS/WSS через хостинг или обратный прокси, поддерживающий
WebSocket. Не запускайте несколько реплик backend: сессии уроков хранятся в
памяти одного процесса и теряются при его перезапуске.

Эта переносимость относится к Docker-хостингам. Платформы только для edge/serverless
Workers, например Cloudflare Workers Free, не запускают Docker Compose и потребуют
отдельной адаптации приложения.

В комплекте есть одно примерное задание по умножению. Замените текст задания,
подсказку и объяснение в `main.py` и `static/index.html`, чтобы добавить свой
учебный материал.
